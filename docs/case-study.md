# Memorize 설계·검증 사례

## 출발점과 담당 범위

AI 코딩 에이전트를 직접 쓰며 세션 간 결정과 진행 상황이 사라지는 문제를 해결하고자 시작했다. 작성자는 단기 관찰·장기 기억 구조와 주요 설계 방향을 정하고 실사용했으며, AI 코딩 에이전트를 구현·테스트·리뷰에 활용했다. 2026 공군창업경진대회 우수상 수상 이력과 현재 저장소의 구현 범위는 구분한다.

## 이벤트를 원본으로 두고 읽기 상태를 재구성하기

수정 가능한 요약만 보관하면 변경 이유와 과거 상태를 잃기 쉽다. Memorize는 append-only 이벤트를 원본으로 두고 projection을 파생 상태로 만들었다. `event-store.ts`·`projector.ts`와 재구성·동기화 테스트가 근거다. 이를 모든 장애에서 무손실이라는 보장으로 확대하지 않는다.

## 로컬 기억과 공유 권한의 경계

오프라인에서도 세션을 시작할 수 있도록 로컬 저장을 우선하고, Hub를 선택적 동기화 경로로 뒀다. 프로젝트·개인·워크스페이스 기억의 접근 경계를 나누고, Hub는 전송과 계정·권한을 분리했다. Hub는 실제 물리 기기 두 대의 동기화를 테스트했고 작성자와 팀원이 실제로 사용했다. 계정 이동·writer 경계 관련 이슈가 남아 있어 설계 의도와 모든 경로의 검증 완료를 동일시하지 않는다.

## 검색 점수와 실제 기억 효용을 구분하기

저장된 LongMemEval-S 결과는 BM25 recall@5 0.966, hybrid 0.978이다. 높은 검색 recall이 수집 단계의 누락이나 최종 답변 품질을 해결하지는 않는다. 실사용의 수집 누락·추출 recall 이슈와 함께 해석해야 한다. 서로 다른 평가 도구의 점수를 그대로 제품 순위로 쓰지 않는다.

## 후속 실험과 종료 판단

기억 도구를 직접 개발·사용하며 생긴 질문은 mori·mori-nest의 에이전트 실행·협업 실험으로 이어졌다. 군 복무의 시간 제약과 모델 API·반복 평가 비용, 관련 도구의 등장을 고려해 추가 개발보다 구현·검증 기록을 명확히 남기는 것으로 마무리했다. 결과와 한계는 [최종 상태](./final-status.md)에 고정한다.
